# Detailed Technical Specification — Epi-Flipboard

## 1. Project Overview

### 1.1 Objective

Develop a web and mobile-first content aggregation and reading platform inspired by Flipboard, enabling users to:

* Access articles from multiple sources (RSS, APIs, web scraping)
* Personalize their content feed by topics of interest
* Save articles for later reading
* Share content easily
* Enjoy a smooth, immersive, and responsive magazine-like experience

### 1.2 Key Goals

* Centralize reliable and diverse information sources.
* Provide an elegant, fast, and personalized user experience.
* Demonstrate the technical feasibility of a scalable, automated content aggregator.
* Lay the foundation for future extensions: AI-based recommendations, analytics, offline mode, and social features.

## 3. Technical Constraints

### 3.1 Tech Stack

* **Frontend:** React + Vite + React Router + TailwindCSS
* **Backend:** Express.js with REST APIs + Mongoose ODM
* **Database:** MongoDB (Local development → MongoDB Atlas for production)
* **Content Sources:** 
  - RSS Feeds (Le Monde, Le Figaro, France Info, RFI, L'Express)
  - APIs: NewsAPI, Guardian API, NY Times API
  - Web Scraping: Puppeteer for Autonews and Jeune Afrique
* **Automation:** Vercel Cron Jobs for scheduled content updates
* **Admin Scripts:** cleanDuplicates.js, fixHtmlEntities.js, populateArticles.js
* **CI/CD:** GitHub Actions
* **Hosting:** Vercel (Frontend + Backend)

### 3.2 Security

* **Authentication:**
  - Passwords hashed with bcryptjs (10 rounds)
  - JWT tokens (7-day expiration with automatic logout on expiry)
  - OAuth 2.0 (Google & Facebook integration)
  - Frontend authFetch wrapper handles token expiration
* **API Security:**
  - JWT verification middleware for protected routes
  - CORS configured with whitelist (localhost + production domains)
  - Bearer token authentication header
  - Admin endpoints protected by authentication
* **Transport Security:**
  - HTTPS mandatory in production (Vercel automatically managed)
  - Secure environment variables (.env excluded from Git)
* **Data Protection:**
  - MongoDB connection secured with credentials (local + Atlas)
  - API keys stored in environment variables only
  - No sensitive data in frontend code
  - HTML entity sanitization on content import
* **GDPR Compliance:**
  - User account deletion capability
  - Data removal on request

## 4. Software Architecture

### 4.1 Components

1. **Frontend (React + Vite):** 
   - Responsive SPA with React Router
   - TailwindCSS for styling
   - Pages: Home, Profile, Favorites, Settings, Admin, Statistics, Newsletter, Article, Search, Collections, Author, Follows, Help, About, Terms, Privacy
   - Components: NavBar with auth modals, Comments, Footer
   - Auth: Custom authFetch wrapper for automatic token expiration handling

2. **Backend API (Express.js):**
   - RESTful endpoints for:
     * Authentication (email/password, OAuth)
     * Posts (CRUD, likes, search)
     * Collections (create, manage, share)
     * Users (profiles, follow system)
     * Comments (create, read)
     * Newsletter (subscription management)
     * Admin tools (duplicates cleanup, entity fixes, content imports)
   - JWT authentication + OAuth (Google, Facebook)
   - Mongoose ODM for MongoDB interactions
   - CORS configuration with whitelist
   - Automated content ingestion with scheduling

3. **Content Aggregation:**
   - RSS parser for multiple French news sources
   - API integrations: NewsAPI, Guardian, NY Times
   - Puppeteer-based scraping for Autonews and Jeune Afrique
   - Automated duplicate detection and cleanup
   - HTML entity decoding on import

4. **Database (MongoDB):**
   - Local: mongodb://localhost:27017/myflip
   - Production: MongoDB Atlas (managed cloud)
   - Collections: users, posts, comments, collections, newsletters
   - Indexes: email (users), url (posts for duplicate prevention)

5. **Deployment:**
   - Frontend: Vercel
   - Backend: Vercel (serverless functions)
   - Cron Jobs: Vercel Cron (daily limit on Hobby plan)
   - Database: MongoDB Atlas (free tier M0)

6. **Testing & Quality:**
   - Backend: Jest + Supertest
   - Frontend: React Testing Library + Vitest
   - Linting: ESLint with custom config
   - CI/CD: GitHub Actions (lint + test on push)
   - Coverage reports generated automatically

## 5. Data Architecture (Simplified)

**Main Collections:**

* **users:** email, passwordHash, name, avatar, isSource, following[], followers[], likedPosts[], timestamps
* **posts:** title, type, author, description, imageUrl, url, content, authorId, likes, likedBy[], timestamps
* **collections:** name, description, userId, posts[], isPublic, timestamps
* **comments:** postId, userId, content, timestamps
* **newsletters:** email, subscribed, verificationToken, verified, timestamps

**Key Relationships:**
* Users can follow other users (many-to-many)
* Users can like posts (many-to-many via likedPosts and likedBy)
* Posts belong to authors (one-to-many)
* Collections belong to users and contain posts (one-to-many and many-to-many)
* Comments belong to posts and users (many-to-one)
